How to integrate geocoding MCP

SmartGeoData exposes geocode_address(text) and geocoding_health() to MCP clients. Geocoding returns up to 10 matches with city-level coordinates, not exact house coordinates.

Start the services

From the project directory, install dependencies and migrate the database, then start Django and the tokenizer worker in separate terminals. Configure a running omlx server and add geographic data to get geocoding results.

make venv
make migrate
make run
./.venv/bin/python manage.py db_worker

The Django API runs at http://127.0.0.1:9112 by default. The MCP process calls this API; it does not start Django, the worker, or omlx.

Option 1: Streamable HTTP

Start the MCP server in another terminal:

make run_mcp

In an MCP client that supports Streamable HTTP, configure the server URL as http://127.0.0.1:9113/mcp. This endpoint is for MCP clients, not a browser page. Check both services:

curl -fsS http://127.0.0.1:9113/health
curl -i http://127.0.0.1:9112/api/health/

The MCP health endpoint checks its process; the API health endpoint returns HTTP 503 until the tokenizers are ready.

Option 2: stdio

For clients that launch local MCP servers, use a configuration like this. Replace /path/to/SmartGeoData with the absolute path to your checkout:

{
  "mcpServers": {
    "smartgeodata": {
      "command": "/path/to/SmartGeoData/.venv/bin/python",
      "args": ["/path/to/SmartGeoData/geo/mcp_server.py"],
      "env": {
        "SMARTGEODATA_API_URL": "http://127.0.0.1:9112"
      }
    }
  }
}

Consult your MCP client's documentation for where to put its configuration. Django and the worker must still be running.

Configuration and safety

SMARTGEODATA_API_URL sets the Django base URL for either transport (default http://127.0.0.1:9112). For HTTP, SMARTGEODATA_MCP_HOST and SMARTGEODATA_MCP_PORT override the default bind address and port (127.0.0.1:9113). Keep the MCP HTTP server on localhost unless you provide authentication and transport security.
